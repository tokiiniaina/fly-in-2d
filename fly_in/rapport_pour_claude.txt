RAPPORT POUR CLAUDE - MIGRATION DES TESTS VERS SOLVER

Contexte
--------
L'application Fly-in utilise désormais Solver et SpaceTimeScheduler au lieu
du glouton Simulator. La demande était de remplacer les usages de Simulator
dans les tests, sans modifier simulator.py ni les autres fichiers.

Modifications effectuées
------------------------

1. tests/test_logic.py
- Remplacement de l'import de Simulator par l'import de Solver.
- Remplacement de Simulator(data).run() par Solver().solve(data).
- Aucune assertion sur un nombre fixe de tours n'a été modifiée.
- Le test compare seulement timeline.total_turns avec len(lines).

2. tests/check_maps.py
- Suppression de l'import de Simulator.
- Suppression de l'import Protocol et de SolverProtocol.
- Suppression du fallback try/except ImportError.
- Suppression des affichages "voie: Simulator" et "voie: Solver".
- Utilisation directe de Solver().solve(data).

Contraintes vérifiées
---------------------
- Aucun autre fichier modifié.
- simulator.py est conservé.
- Plus aucune occurrence de Simulator dans les deux fichiers modifiés.
- Lignes de 79 caractères maximum.
- flake8 ciblé : OK.
- mypy ciblé : OK.

Tests
-----
Commande exécutée :

python -m pytest tests -q

Résultat :

9 failed, 96 passed in 6.28s

Échecs observés
---------------
- test_prop_clearance_rule : zone "junction" absente du plan.
- test_pad_uses_the_map_color : zone "goal" absente du plan.
- test_difficulty_and_label : difficulté None au lieu de EASY.
- test_bad_landing_is_rejected : token D1-junction non reconnu.
- test_restricted_flight_takes_two_turns : aucun drone en vol à l'état testé.
- test_hud_text_is_safe_for_ursina : EASY_SIMPLE_FORK absent du HUD.
- test_scene_matches_the_map : 6 pads au lieu de 5.
- test_drones_sit_on_real_positions : zone "junction" absente.
- test_hud_matches_backend : 7 tours au lieu des 5 attendus.

Analyse
-------
Les modifications demandées sont terminées et les contrôles ciblés passent.
Les échecs viennent probablement de la migration du viewer et des tests vers
Solver :

- certains tests attendent encore les résultats du glouton Simulator ;
- le parser TimelineBuilder peut devoir accepter le nouveau token de vol :
  D<ID>-<origine>-<destination> ;
- plusieurs tests attendent encore des cartes, noms de zones ou nombres de
  tours correspondant à l'ancien comportement ;
- certains échecs semblent liés aux cartes ou au viewer indépendamment du
  remplacement demandé.

Décision attendue
-----------------
Choisir l'une des options suivantes :

1. Accepter les modifications actuelles et traiter les 9 échecs séparément.
2. Mettre à jour les tests du viewer pour Solver.
3. Corriger TimelineBuilder pour le nouveau format des tokens de vol.
4. Réviser les attentes de nombre de tours produites par Solver.
5. Ne rien modifier de plus pour le moment.
